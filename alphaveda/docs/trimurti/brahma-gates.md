# Brahma Gate — Understand and Create

Source: PDF pp.5-6, 22. Applies before any new AlphaVeda feature enters design.

## Brahma objectives (source p.6, adopted as-is)
- Understand investor segments
- Understand actual decision behaviours
- Define portfolio problems
- Identify emotional and cognitive risks
- Establish evidence and data requirements
- Define success and harm metrics
- Determine what should not be automated
- Convert findings into product requirements

## Brahma outputs (source p.6)
1. Investor behaviour map
2. User classifications
3. Jobs-to-be-done
4. Decision-risk register
5. Data and evidence requirements
6. User journey
7. Feature scope
8. Information architecture
9. Product success metrics
10. Human-approval boundaries

## Brahma review scorecard (source p.22)

| Review dimension | Question |
|---|---|
| User need | Does this solve a validated problem? |
| Behaviour | Does it account for actual decision behaviour? |
| Evidence | Are required data and assumptions defined? |
| Scope | Is the feature appropriately bounded? |
| Success | Are benefit and harm metrics measurable? |

## Gate rule

A release does not proceed solely because the combined Brahma+Vishnu+Shiva score is high — a
critical failure in any single Brahma dimension (e.g. no validated user need) blocks release on
its own, same rule as Shiva's gate below.
