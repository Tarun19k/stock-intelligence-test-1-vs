# Vishnu Gate — Preserve and Operate

Source: PDF pp.6-7, 22. Applies during UX/design work, after Brahma's gate has passed.

## Vishnu objectives (source p.6, adopted as-is)
- Create predictable navigation
- Preserve user context
- Make data and recommendations understandable
- Minimise unnecessary portfolio activity
- Maintain trust through consistency
- Provide enough explanation without overwhelming users
- Protect existing user decisions unless valid new evidence emerges

## Reconsideration triggers (source p.7) — the only valid reasons to reopen a prior user decision
- Investor circumstances changed
- Portfolio constraints changed
- Tax assumptions changed
- Source data became invalid
- Recommendation risk materially changed
- Previous decision expired

## Vishnu outputs (source p.7)
1. Information architecture
2. Low-fidelity wireframes
3. Interaction patterns
4. Decision-comparison system
5. Content and terminology system
6. Design system
7. Accessible prototype
8. Behavioural guardrails
9. Empty, error and blocked states
10. Instrumentation plan

## Vishnu review scorecard (source p.22)

| Review dimension | Question |
|---|---|
| Comprehension | Can users understand the decision? |
| Stability | Does the interface avoid reacting to noise? |
| Consistency | Are terminology and interactions predictable? |
| Control | Can users inspect, decline and modify options? |
| Accessibility | Can different users operate the experience? |

## Gate rule

Same as Brahma's and Shiva's: a critical failure in any one Vishnu dimension blocks release
regardless of the combined score.
